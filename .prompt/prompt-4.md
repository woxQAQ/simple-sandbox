# 测试架构

遵循本项目的规范，所有的e2e测试代码都放在 tests/e2e 下，以下是e2e测试的大致框架

```
tests/e2e
  common/ # 共用逻辑
    containers.py # 用于容器操作，包括启动，关闭，创建，检查容器状态等。可以预留出适配多种容器后端的接口，但是本项目仅考虑实现docker
    config.py # 存放e2e测试的配置信息，读取.env文件
    client.py # 共用的与sandbox api进行交互的代码
  suites/ # 存放测试套件
    test-python-codes.py # 测试python代码能否正常运行和返回结果，需要覆盖插件逻辑，危险系统调用逻辑，正常系统调用逻辑
    test-nodejs-codes.py # 测试nodejs代码能否正常运行和返回结果，需要覆盖插件逻辑，危险系统调用逻辑，正常系统调用逻辑
  .env # 存放e2e测试的环境变量
  .env.example # 由于 .env 不会被写入 git tree，留出 example 文件用于提示
  e2e.py # e2e测试的入口，用于启动容器，等待容器状态，运行套件和关闭容器和输出测试报告的测试全流程
  Makefile # 存放用于e2e测试的快捷命令
```

- 请你严格遵循上述的文件框架和各文件的作用，在此框架基础上，你可以适当扩展你的逻辑
- 当你需要安装任何依赖时，请你使用 `uv add <pkg> --dev` 安装到 dev group 中
- 请你参考python编写测试的最佳实践
- 最后请你输出一份e2e的测试报告，内容包括插件逻辑的测试结果，危险调用的测试结果等
- 请你不要在本地开启服务器来进行测试
