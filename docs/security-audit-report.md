# 沙盒管理器安全审计报告

## 概述

本文档记录了对 simple-sandbox 项目的安全审计结果，发现了多个严重和中等级别的安全漏洞，需要立即修复。

## 审计时间

**审计日期**: 2025-08-14  
**审计版本**: feat/go-port-fs-enhanced 分支  
**审计范围**: 完整代码库安全分析

## 🔴 严重安全漏洞 (Critical)

### 1. Node.js 运行时代码注入漏洞

**风险等级**: 🔴 严重  
**影响**: 完全系统 compromise  
**位置**: `docker/runtimes/node/runner.js:54`

**问题描述**:
- 使用 `eval()` 直接执行任意用户代码
- 没有任何代码过滤或沙盒化机制
- 恶意代码可以直接访问 Node.js 全局对象和模块系统
- 可能导致：
  - 文件系统读写
  - 网络访问
  - 进程创建
  - 系统命令执行

**漏洞代码**:
```javascript
// 执行用户代码，存在严重安全漏洞
eval(code);
```

### 2. 环境变量敏感信息泄露

**风险等级**: 🔴 严重  
**影响**: 代码泄露，多租户隔离失效  
**位置**: `internal/sandbox/podman/manager.go:84`

**问题描述**:
- 将完整用户代码通过环境变量 `SANDBOX_CODE` 传递
- 环境变量可能被其他进程读取
- 在多租户环境中存在严重安全隐患
- 系统进程可能通过 `/proc` 文件系统读取环境变量

**漏洞代码**:
```go
fmt.Sprintf("--env=SANDBOX_CODE=%s", req.Code)
```

### 3. 文件系统权限配置不当

**风险等级**: 🟡 中等  
**影响**: 信息泄露，权限提升  
**位置**: `internal/sandbox/podman/manager.go:51-56`

**问题描述**:
- 临时目录权限设置为 0755，过于宽松
- 文件权限设置为 0755，允许其他用户读取
- 缺少文件系统挂载的额外安全选项

## 🟡 中等安全问题 (Medium)

### 4. Seccomp 配置不完整

**风险等级**: 🟡 中等  
**影响**: 系统调用逃逸  
**位置**: `internal/security/seccomp/*.json`

**问题描述**:
- Python 配置允许过多系统调用
- Node.js 配置允许 `clone`, `fork` 等危险系统调用
- 缺少针对特定语言的精细化过滤规则

### 5. Kubernetes 运行时安全配置不足

**风险等级**: 🟡 中等  
**影响**: 容器逃逸，权限提升  
**位置**: `internal/sandbox/k8s/manager.go:82-127`

**问题描述**:
- Pod 安全配置过于简单
- 缺少 `SecurityContext` 和 `PodSecurityContext` 配置
- 没有启用 Pod 安全策略或安全上下文约束

### 6. API 缺少安全控制

**风险等级**: 🟡 中等  
**影响**: 未授权访问，DoS 攻击  
**位置**: `internal/api/server.go:42-66`

**问题描述**:
- 没有身份验证机制
- 缺少请求频率限制和 IP 白名单
- 没有防止暴力攻击的保护措施

### 7. 资源限制配置不够严格

**风险等级**: 🟡 中等  
**影响**: 资源耗尽攻击  
**位置**: `internal/constants/const.go:33-37`

**问题描述**:
- 默认 PID 限制为 128，过高
- 缺少对 CPU 核心数的严格限制
- 没有设置磁盘空间限制

## 🟢 轻微安全问题 (Low)

### 8. 日志信息可能泄露敏感数据

**风险等级**: 🟢 轻微  
**影响**: 信息泄露  
**位置**: 多个日志记录点

**问题描述**:
- 错误日志可能包含容器内部信息
- 调试信息在生产环境中未完全禁用

### 9. 容器镜像缺少安全扫描

**风险等级**: 🟢 轻微  
**影响**: 漏洞利用  
**位置**: `docker/runtimes/*/Dockerfile`

**问题描述**:
- 基础镜像没有定期安全更新
- 缺少漏洞扫描和最小化原则

## 修复建议

### 🔴 立即修复 (Critical)

#### 1. 修复 Node.js eval 漏洞
```javascript
// 使用 VM 模块替代 eval
const vm = require('vm');
const context = vm.createContext({
  console: console,
  require: require, // 限制 require 访问
  // 只暴露安全的全局对象
});
vm.createContext(context);
const result = vm.runInContext(code, context, {
  timeout: 5000,
  displayErrors: true
});
```

#### 2. 移除环境变量代码传递
- 改为使用只读文件系统挂载
- 确保 Podman 容器无法访问环境变量

#### 3. 加强文件系统权限
- 设置临时目录权限为 0700
- 设置代码文件权限为 0400
- 添加 `noexec`, `nosuid`, `nodev` 挂载选项

### 🟡 短期修复 (Medium)

#### 4. 完善 Seccomp 规则
- 为每种语言创建最小化系统调用集合
- 移除不必要的系统调用
- 添加针对特定危险系统调用的额外限制

#### 5. 增强 K8s 安全配置
```yaml
securityContext:
  runAsUser: 65532
  runAsGroup: 65532
  runAsNonRoot: true
  readOnlyRootFilesystem: true
  allowPrivilegeEscalation: false
  capabilities:
    drop:
      - ALL
```

#### 6. 添加 API 安全控制
- 实现 JWT 或 API Key 认证
- 添加请求速率限制
- 实现 IP 白名单机制

#### 7. 严格资源限制
- 降低 PID 限制到 64
- 添加 CPU 核心数限制
- 实现磁盘空间监控

### 🟢 长期改进 (Low)

#### 8. 改进日志安全
- 移除调试信息
- 实现日志脱敏
- 添加日志访问控制

#### 9. 容器镜像安全
- 使用最小化基础镜像
- 定期更新依赖
- 实现自动化安全扫描

## 修复优先级

1. **立即修复**: Node.js eval 漏洞，环境变量泄露
2. **1周内修复**: 文件权限，Seccomp 规则
3. **2周内修复**: K8s 安全配置，API 认证
4. **1月内修复**: 资源限制，日志安全，镜像安全

## 验证方法

修复后需要通过以下测试验证安全性：

1. **代码注入测试**: 尝试执行危险系统调用
2. **权限测试**: 验证文件系统访问权限
3. **资源测试**: 验证资源限制是否生效
4. **网络测试**: 验证网络隔离是否有效
5. **逃逸测试**: 尝试容器逃逸攻击
